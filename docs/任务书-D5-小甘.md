## 一、升级 `patch`：从「建议」到「可落地补丁」（核心，约 2h）

1. 按 `issue.category` 给出**对应类型的修复片段**（`ai.py` 里 `SYSTEM_PROMPT` 或 `_MOCK_KNOWLEDGE` 扩展模板），例如：
   - `seo`（缺 meta/title/H1）→ 一段 HTML `<head>` 补全片段
   - `ssl`（证书将过期）→ 证书续期 / 自动续签配置（如 certbot 命令提示）
   - `performance`（响应慢）→ Nginx 缓存 / 静态资源压缩配置片段
   - `link_server_error` / `link_unverified` → 说明「先复测，勿急删」+ 若确为死链给替换/删除示例
2. **必须用码道 CodeArts 来生成补丁**：用你机器上装的 `D:\CodeArts Agent\`（独立客户端），针对具体 issue 让码道生成修复代码片段，把结果回灌到 `patch` 字段。**保留码道会话/日志**——这是「用了华为技术」的直接证据（赛题硬性要求）。
3. 提示词加硬约束：**禁止编造不存在的文件路径 / 命令**；`patch` 必须与 issue 类别严格对应；无法给出确定性补丁时，`patch` 留空并说明原因，绝不瞎编。

## 二、闭环验证（约 0.5h）

4. 用 `diagnose_demo.py` 三套报告（全正常 / 有 P1 死链 / SSL 将过期）跑通，确认 `patch` 字段非空且内容可执行、与类别匹配。
5. 真模型（队长 `.env` 已配 `deepseek-v4-flash`）跑一次，对比 mock 与真模型的 `patch` 质量差异；挑差异点调提示词。
