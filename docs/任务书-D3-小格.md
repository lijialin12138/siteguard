## 二、今日三件事（按优先级）

### 1️⃣ 对齐「三档链接」的呈现（最重要，产品可信度全靠它）

后端报告里的链接问题是**分三档**的，含义严格不同，前端**必须分开显示，不能合并成一个「死链数」**：

| 档位 | 含义 | 怎么显示 |
|---|---|---|
| 失效 `404/410` | 真死链，必须修 | 红色，标「失效」 |
| 服务端错误 `5xx` | 可能瞬时故障，先复测 | 橙色，标「服务端错误」 |
| 无法验证 `403/429/超时` | **不等于失效**，需人工抽查 | 灰色，标「待确认」 |

- 数据来源：`GET /api/overview` 每个站点已带 `broken_links`（失效数）、`link_server_error`、`link_unverified` 三个字段。
- **验收**：三个数字用不同颜色 + 标签展示；展开能看到对应链接示例。

> 为什么要较真：把限流/反爬误报成「死链」，会让客户去修一堆本来好好的链接，报告直接失去可信度。这是这类工具最典型的翻车方式。

### 2️⃣ 打磨三种状态

空态（还没加站点）、加载态（巡检进行中）、错误态（接口失败）—— 都要有明确反馈，不能白屏。

### 4️⃣ MaaS 已接通：验证「AI 诊断」面板能正确渲染真模型结果

队长已把华为云 MaaS 跑通（`deepseek-v4-flash` 真模型），后端 `GET /api/scans/{scan_id}` 返回的 `diagnosis` 字段就是模型产出。注意：**真实模型和内置模拟的返回结构完全一致**，所以你用 mock 数据也能测渲染；但真通了之后建议抽查一次真实结果，确保没有字段错位。

真模型诊断 JSON 结构（你要渲染的就是这些字段）：

```json
{
  "summary": "一句话健康状况（40字内）",
  "severity": "P0 | P1 | P2 | P3",
  "root_causes": [{"issue": "现象", "reason": "根因"}],
  "actions": [{"priority": 1, "action": "做什么", "how": "怎么操作"}],
  "patch": "修复片段，没有则为空串",
  "_meta": {"model": "deepseek-v4-flash", "total_tokens": 1487}
}
```

- 把 `summary` / `severity` / `root_causes[].reason` / `actions[].how` / `patch` 都展示出来（`patch` 用代码块渲染）。
- 💡 **答辩加分项**：当 `_meta.model` **不是** `mock-diagnosis` 时，在面板角落显示一个「由华为云 MaaS 大模型诊断」小徽标 —— 评委一眼能看到我们真用了华为技术。
- 抽查方法：让队长跑一次真实诊断，把返回的 JSON 贴你，你对照字段看渲染有没有空白 / 错位。
