## 1. 三套用例对比（mock vs 真模型）

### 用例0 · 全部正常（`issues=[]`）

| 项 | MOCK | 真模型 |
|----|------|--------|
| severity | P3 | **P2** |
| 根因 | 无 | 页面 `title` 为空、缺 `meta description` |
| patches | `[]`（空） | 1 段：`seo` |

真模型 `seo` 补丁（html）：
```html
<head>
    <title>这里填写页面标题（例如：Demo测试站点）</title>
    <meta name="description" content="这里填写页面的简要描述，控制在160字符以内。">
</head>
```

> **差异点 A（真模型更敏锐）**：mock 只依据 scanner 的 `issues` 列表，本例 `issues=[]` 就判"全正常"；真模型额外看了 `_slim_report` 的原始信号（`has_meta_description=false`），抓出了 mock 漏报的 SEO 缺口。
> 注意：生产环境应让 scanner 把"缺 title/meta"也纳入 `seo` issue，否则与契约"patches.category 须与 issues 一致"略有张力。本例属 demo 报告 `issues` 人工置空所致。

### 用例1 · P1 失效链接（`broken_link`）

| 项 | MOCK | 真模型 |
|----|------|--------|
| severity | P1 | P1 |
| patches | 1 段 `broken_link`（html 改 `<a href>` + nginx 301 注释） | 1 段 `broken_link`（nginx `location = /404 { return 301 ... }`） |

真模型补丁（nginx，首轮干净输出，可作代表）：
```nginx
location = /404 {
    return 301 https://demo.test/;
}
```

> **差异点 B（补丁风格不同，均合规）**：mock 偏前端改 `<a>` 标签，真模型偏运维 nginx 301 重定向，都可直接落地，无对错。
> **鲁棒性风险（见第 3 节）**：本轮真实模型对该用例返回的内容偶发无法被 JSON 解析，已触发 `_extract_json` 兜底。

### 用例2 · SSL 证书 3 天内过期（`ssl`）

| 项 | MOCK | 真模型（调优后） |
|----|------|------|
| severity | P1 | P1 |
| patches | 1 段 `ssl`：安装 certbot + 续期 + `renew --dry-run` + cron 自动续期 | 1 段 `ssl`：安装 certbot（若未装）+ `renew --quiet` + 每日 cron 自动续期 + `nginx -s reload` |

真模型补丁（bash，调优后）：
```bash
# 1. 安装certbot（若未安装）
if ! command -v certbot &>/dev/null; then
    apt-get update && apt-get install -y certbot python3-certbot-nginx
fi

# 2. 手动触发续期（仅针对即将到期的证书）
certbot renew --quiet

# 3. 配置每日自动续期（添加到crontab）
(crontab -l 2>/dev/null | grep -v certbot; echo "0 3 * * * /usr/bin/certbot renew --quiet && /usr/sbin/nginx -s reload") | crontab -

# 4. 立即重载nginx使新证书生效
nginx -s reload
```

> **差异点 C（已通过提示词调优追平）**：调优前真模型只给 `certbot renew`（假设已装，不完整）；mock 给了完整"安装+续期+dry-run+cron"。已在 `SYSTEM_PROMPT` 增加第 8 条硬约束（ssl 必须含自动续期 + 定时任务 + reload），调优后真模型补丁已与 mock 对齐，落地完整。

## 2. 契约合规性核验

对真模型所有可解析输出核验：

- `patches[].category` 均在 scanner 的 11 类内（seo / broken_link / ssl）✅
- `patches[].code` 均非空 ✅
- `link_unverified` 类未出现在本三例；按契约铁律，该类只给复核命令、不给删除 ✅（mock 已验证）
- 旧字段 `patch` 保留兜底，与后端 `service.extract_patches()` 契约一致 ✅

## 3. 真模型鲁棒性风险（需 production 处理）

- **现象**：本轮「用例1_P1失效链接」真实模型返回内容偶发无法被 `json.loads` 解析，`ai._extract_json` 兜底返回 `{"summary": "模型返回内容无法解析为 JSON", "raw": ...}`。
- **根因**：模型偶发在 JSON 字符串值内换行 / 转义不当，产生非法 JSON（LLM 输出 JSON 的常见问题，与温度 `0.2` 有关）。
- **建议（不在本 D5 强制，但建议跟进）**：
  1. `diagnose()` 解析失败时**重试一次**（换 temperature 或同参数）；
  2. 若 MaaS 支持，开启模型 **JSON 模式**（response_format=json_object）；
  3. 前端对兜底结果做友好提示（"模型输出异常，请重试"），不要渲染空白。
- mock 模式不受此影响，永远稳定可演示。

## 5. 本次顺带的提示词调优

`app/ai.py` 的 `SYSTEM_PROMPT` 新增第 8 条：

> ssl 类补丁必须给出可落地的续期方案：若服务器尚未安装 certbot，先给安装步骤；续期命令要包含自动续期（`certbot renew --quiet`）与定时任务（cron 或 systemd timer）配置，不要只给一次性 renew 命令；并在续期后 reload 一次 Web 服务（如 `nginx -s reload`）。

效果：用例2 真模型补丁从"只 renew"升级为"安装+续期+cron+reload"，与 mock 对齐。
