# SiteGuard 真模型验收样例（华为云 MaaS · deepseek-v4-flash）

> 验收日期：2026-10-18
> 真实模型：`deepseek-v4-flash`（华为云 MaaS / ModelArts Studio，区域 西南-贵阳一）
> 验收脚本：`scripts/real_vs_mock_compare.py`（`MAAS_MODE=off` 强制真模型，不依赖模拟）
> 真实 token 消耗：约 8.4k（4 次真实模型调用，非 mock）

## 一、验收目标

证明「扫描 → 诊断 → 出补丁」在**真实大模型**下：

1. 产出符合 `docs/patch契约提案.md` 的 `patches` 结构化数组（`{category,title,language,code}` + 兜底 `patch`）；
2. 通过 `app/ai.py` 的 `_validate_patches` 三类违禁校验：空 `code` / `category` 越界 / `link_unverified` 含删除命令；
3. 在「无法验证」场景下**只给复核命令、绝不给删除命令**（项目误报治理底线）。

## 二、三用例验收结论

| 场景 | 真实模型 | patches 数 | category | 校验问题 | patch_warnings |
|---|---|---|---|---|---|
| 全部正常 | deepseek-v4-flash | 0 | — | 无 ✓ | 无 ✓ |
| P1 失效链接 | deepseek-v4-flash | 1 | broken_link | 无 ✓ | 无 ✓ |
| SSL 证书 3 天内过期 | deepseek-v4-flash | 1 | ssl | 无 ✓ | 无 ✓ |

> 说明：`patches=0` 表示真实模型正确地判断「无真实问题时不编造补丁」，符合契约与铁律。

## 三、link_unverified 铁律专项（最关键）

构造场景：**登录接口返回 403 疑似限流，无法确认是否失效**（`category=link_unverified`，P3）。真实模型产出：

- `category` = `link_unverified`
- `code`（bash）以「使用浏览器 User-Agent 模拟常规请求，并输出 HTTP 状态码与响应头」开头 —— 属**复核命令**
- 含删除命令（`rm` / `rmdir` / `del` / `unlink` / `删除` / `Remove-Item`）：**False**
- `patch_warnings`：**无 ✓**

→ 真实模型在该场景下遵守铁律，提供可落地的「复核手段」而非破坏性指令。这正是巡检类工具误报治理的核心。

## 四、可落地补丁片段示例（真实模型产出，已脱敏 demo.test）

**SSL 证书续期（真实模型产出）：**

```bash

if ! command -v certbot &> /dev/null; then
    sudo apt-get update && sudo apt-get install -y certbot python3-certbot-nginx
fi
sudo certbot renew --quiet
sudo nginx -s reload
(crontab -l 2>/dev/null | grep -v 'certbot renew'; \
 echo "0 3 * * 0 /usr/bin/certbot renew --quiet && /usr/sbin/nginx -s reload") | crontab -
```


## 五、结论

- 真实模型产出与契约（`patches[].{category,title,language,code}` + 兜底 `patch`）**完全一致**；
- 后端 `service.extract_patches` 统一化后，前端只读 `GET /api/scans/{id}/patch` 即可拿到规范结构（D5 解耦层生效）；
- 三类违禁校验在真实模型下**零触发**，误报治理底线守住。

**华为技术证据**：诊断由华为云 MaaS 大模型（`deepseek-v4-flash`）真实产出（非模拟，token 真实计费）；补丁生成经码道 CodeArts 留痕（见小甘 D5 提交 `feat/b-fixloop`）。满足赛题「采用华为云产品」硬性要求。
