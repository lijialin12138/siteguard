## 一、Dashboard 深化（约 1.5h）

1. **站点健康状态灯**：站点列表里每个站点一个灯——**红 = 有异常（任一 issue 非空且 severity≥P2）/ 绿 = 正常**。配色严格遵循计划要求「红色代表异常、绿色代表正常」，让评委一眼看出问题站点。
2. **AI 建议卡片**：诊断结果里取 `severity`（P0–P3）+ `summary`，做成卡片，severity 用对应色块；点击展开 `root_causes` / `actions`。
3. 站点列表 + 健康灯 + 趋势图 + 建议卡片，四个区块在一屏内合理排布（单页 HTML，不引构建工具）。

## 二、修复闭环前端（D5 重头戏，约 2h）

后端已经给了现成链路，你**链式调用即可**，不用新接口：

```
扫描站点  → POST /api/sites/{id}/scan        → 拿到 scan_id
取结果    → GET  /api/scans/{scan_id}
AI 诊断   → POST /api/scans/{scan_id}/diagnose  → 返回 {summary, severity, root_causes, actions, patch, _meta}
```

在这条链路上加两个交互：

4. **「一键复制修复片段」**：诊断面板里 `patch` 字段（已有渲染，见 `renderDiag` 477 行）加复制按钮（`navigator.clipboard.writeText`）。
5. **「应用修复后重新巡检」按钮**：点它 → 对该站点再跑一遍上面的 scan → diagnose → 渲染，并在 UI 上**对比前后**：若原本的 issue 这次没出现，提示「✅ 该问题已修复」；仍出现则「⚠️ 问题仍存在」。这就是「发现问题 → AI 给方案 → 复扫验证」的完整闭环，评委最想看。
   - 注意：我们**不自动改远程网站**（计划避坑明确"不要一上来追求全自动修复"），闭环是「AI 给补丁 + 用户应用 + 复扫确认」，足够演示且更稳。
