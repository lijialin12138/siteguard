# 华为技术使用说明（答辩专版）

> 适用场景：初赛 / 总决赛现场，向评委说明"本项目确实使用了赛题要求的华为技术"。
> 本文只写**对外可讲、可现场复现**的内容，不含内部调试细节。

---

## 一、我们用到了哪些华为技术

本项目落地了赛题「基于华为云产品打造 AI 创新应用」要求的两条华为技术主线：

| 华为技术 | 在本项目中的角色 | 关键证据 |
| --- | --- | --- |
| **码道 CodeArts Agent** | 生成 / 校对「网站修复补丁」候选片段 | `docs/codearts-evidence/`（6 张会话截图 + 提示词） |
| **华为云 MaaS（大模型即服务）** | 对巡检结果做 AI 诊断，产出修复建议 | `docs/真模型验收样例.md`（真实模型产出，非模拟） |

两条线共同支撑 SiteGuard 的核心能力：**自动巡检 → AI 诊断 → 给出可落地修复补丁**。

## 二、码道 CodeArts 使用说明

### 1. 用它做什么
SiteGuard 的「修复补丁」不是凭空编的，而是先由**码道 CodeArts** 针对每类网站问题生成候选修复片段，再由项目内置的硬约束（`app/ai.py` 的 `SYSTEM_PROMPT` + `_MOCK_KNOWLEDGE`）**做校对与兜底**，通过后才沉淀进产品。这正是 D5 patch 管线的「生成 / 校对」设计。

### 2. 实际怎么用的（如实说明）
- 在码道 CodeArts 客户端中，按 6 类网站问题（ssl、失效链接、性能、SEO、无法验证链接、5xx 链接）**逐类发送提示词**；
- 码道返回补丁片段后，**对整段问答截图留档**（截图同时包含"发送的提示词 + 返回的补丁 JSON"）；
- 截图归入 `docs/codearts-evidence/`，作为"使用了华为技术"的物证。

> 答辩口径：**"我们在码道客户端逐类生成补丁并截图留档"**。若评委要求现场复现，直接打开码道客户端、粘贴任意一条提示词即可当场演示，比拿日志更有说服力。

### 3. 覆盖的 6 类补丁

| 类别 | 补丁内容 | 取证要点 |
| --- | --- | --- |
| `ssl` | certbot 续期 + crontab 自动续期 | 截图含 crontab + `--post-hook nginx -s reload` + dry-run |
| `broken_link` | HTML 改 `<a href>` + Nginx 301 | 截图含 HTML 修复 + Nginx 301 两项 |
| `performance` | Nginx 开启 gzip + 静态资源缓存 | 截图含 gzip 限定类型 + 长缓存配置 |
| `seo` | 补全 `<head>` 基础 SEO 标签 | 截图含 `<title>` + `meta description` + 唯一 `<h1>` |
| `link_unverified` | **仅复核命令，无删除**（控误报铁律） | 截图确认全是 `curl` 只读复核，无任何删除操作 |
| `link_server_error` | 复测 3 次确认是否瞬时故障，非上来就删 | 截图含"复测 → 区分维护与死链 → 才替换"流程 |

### 4. 关键的合规底线（答辩加分项）
`link_unverified`（403/429/超时，无法验证）和 `link_server_error`（5xx）两类，码道给出的**全部是复核 / 复测命令，没有任何删除操作**。我们的理念是：**无法验证 ≠ 死链，误删会烧掉客户真实链接**。这条"控误报"铁律，在码道产出和真模型产出里都守住了。

### 5. 证据位置
```
docs/codearts-evidence/
├── README.md          # 证据包说明（提示词 + 基准补丁 + 校对记录）
├── prompts.txt        # 6 类提示词纯文本
└── *.png              # 6 张码道会话截图（ssl / broken_link / performance / seo / link_unverified / link_server_error）
```

## 三、华为云 MaaS 使用说明

### 1. 用它做什么
巡检引擎收集到网站健康数据后，由**华为云 MaaS 大模型**做根因分析，并产出结构化修复建议（`patches` 数组）。

### 2. 是真实模型，不是模拟
- 模型：`deepseek-v4-flash`（部署于华为云 MaaS，贵阳一节点）；
- 诊断时真实消耗 token（验收样例实测单次约 2590 token、三用例累计约 8.4k token）；
- 证据见 `docs/真模型验收样例.md`，含真实模型返回的补丁片段与 `_meta`（模型名、token 消耗），不含任何密钥。

### 3. 真模型下的质量验证
- 三用例（全部正常 / 失效链接 / SSL 临期）均产出合法 `patches`，无空 code、无越界 category；
- 专门补测"403 疑似限流、无法确认失效"场景：真实模型给出的是**复核命令**，**没有任何删除指令**——误报治理底线在真实产出下同样守住。

## 四、答辩应答要点（可现场照念）

**Q：你们真用了华为技术吗？怎么证明？**
A：用了两条。一是码道 CodeArts，我们针对 6 类网站问题在客户端逐类生成修复补丁并截图留档（证据在 `docs/codearts-evidence/`）；二是华为云 MaaS，`deepseek-v4-flash` 真实模型做诊断，token 真实计费（证据在 `docs/真模型验收样例.md`）。两条都能现场复现。

**Q：为什么工具不直接自动改客户的网站？**
A：因为未授权修改他人系统既不合规也不安全。SiteGuard 的定位是"体检医生"——只出诊断和处方，改不改、怎么改决定权在客户手里。这既是我们产品的边界，也是合规底线。

**Q：你们怎么控制误报？**
A：链接探测分三档——失效（404/410）、服务端错误（5xx）、无法验证（403/超时）。对"无法验证"的链接，我们一律只给复核命令、绝不给删除，避免把"反爬/限流"误判成死链让客户去删真实链接。这条在码道产出和真模型产出里都校验过。

**Q：补丁靠谱吗？会不会编造？**
A：双保险。码道生成候选补丁后，再由项目内置的硬约束做校对——禁止编造不存在的文件路径、命令、域名；空 code、越界 category、违规删除命令都会被拦截。我们保留的校对记录里，连码道的小瑕疵都如实记录了，说明我们是真校对、不是照单全收。
