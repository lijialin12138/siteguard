# SiteGuard · AI 自动化企业网站维护助手

> 第十一届华为ICT大赛 · 创新赛 · 赛题一：基于华为云产品打造 AI 创新应用

企业网站常年存在一类"没人管"的问题：证书快过期没人知道、页面挂了没人发现、外链死了没人清理。
SiteGuard 用**自动巡检 + AI 诊断 + 修复建议生成**，把这件事从"人工定期抽查"变成"系统自动闭环"。

## 它做什么

```
配置站点 → 定时自动巡检 → 发现异常并落库 → AI 诊断根因 → 生成修复建议与补丁 → 控制台展示
```

巡检项：

| 类别 | 检查内容 |
|---|---|
| 可用性 | HTTP 状态码、是否可访问、fetch 错误 |
| 性能 | 响应耗时（≥2s 预警，≥5s 告警） |
| 安全 | SSL 证书剩余有效天数（≤15 天预警，已过期告警） |
| 内容 | 链接探测（页面内链逐个复核） |
| SEO / 无障碍 | title、meta description、H1 数量、图片 alt 缺失数 |

问题按 P0–P3 分级，再把结构化问题交给大模型分析根因和处置方案。

### 链接问题为什么分三类，而不是一个"死链数"

这是本项目在**误报控制**上的核心设计，也是巡检类工具最容易翻车的地方。

最初版本只用 `HEAD` 请求探测内链，拿不到有效响应就判为死链。实测某高校官网首页报出
**20 个死链，其中 18 个是误报**——18 条微信公众号文章链接之所以"失败"，仅仅是因为
这类站点对 HEAD 请求直接断连，改用 `GET` 全部返回 200。

修掉之后还剩第二个坑：连续点几次巡检，该站又有 6 个子站链接返回 **403**。
但隔几分钟用**完全相同的请求**复测，6 条全部恢复 200。说明 403/429 这类状态码的含义是
**"拒绝服务"（反爬、限流、需登录）而不是"资源不存在"**，浏览器往往能正常打开。

修正后的策略：

1. **二次复核**：`HEAD` 失败或返回 4xx/5xx 时，一律用 `GET` 再确认一次，只有 GET 也失败才算有问题；
2. **只有 404 / 410 判失效**，其余 4xx（401/403/407/429…）一律归入"待人工确认"；
3. **按性质分桶**，三者的处理方式完全不同：

| 桶 | 判定依据 | 等级 | 含义 |
|---|---|---|---|
| `broken_links` | 确认 404 / 410 | P1 | 资源确实不存在，可以直接改 |
| `server_error_links` | 返回 5xx | P2 | 对方服务端故障，**可能是瞬时的**，应先复测 |
| `unverified_links` | 连不上 / 403 / 429 等 | P3 | **无法验证，不等于失效**，只提示人工抽查 |

同一次巡检的对比结果：

```
修复前：死链 20 个（18 个误报）
中间态：失效链接 6 个（全是 403，复测后全部正常 → 仍是误报）
修复后：确认失效 0 个 · 服务端错误 1 个 · 无法验证 4 个
```

把"无法验证"直接说成"死链"，会让用户去修本来没坏的链接，这份报告也就没人信了。
所以前端 Dashboard 把它们分开显示，诊断结论里也禁止大模型混用这三个概念。

> 顺带学到的一条工程经验：**巡检类工具的核心指标不是"发现多少问题"，而是误报率。**
> 高频巡检很容易触发对方站点的限流，把限流误判成故障，是这类工具最典型的翻车方式。

## 快速开始

### 1. 装依赖

```bash
cd siteguard
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

python -m pip install -i https://mirrors.aliyun.com/pypi/simple/ -r requirements.txt
```

> **两件事必须注意：**
>
> 1. 如果 `pip` 提示找不到命令，一律改用 `python -m pip`。
> 2. **国内一定要加 `-i` 指定镜像源**，直连 pypi.org 大概率超时。首选清华源
>    `https://pypi.tuna.tsinghua.edu.cn/simple`；如果它返回 `from versions: none`
>    （限流时会这样），换阿里云源即可正常安装。

### 2. 配置华为云 MaaS

```bash
copy .env.example .env          # Windows
# cp .env.example .env          # macOS / Linux
```

然后编辑 `.env`，填入三个值：

1. **区域选「西南-贵阳一」** —— 免费额度只在这个区域开放
2. 控制台顶部搜索框搜 `MaaS` → 进「ModelArts Studio / MaaS 模型即服务」控制台
3. 左侧 **模型推理 → 在线推理 → 预置服务** → 选 DeepSeek 一类模型 → **领取额度**
   → 点「**调用说明**」复制 **API 地址**（删掉末尾的 `/chat/completions`，只留到 `/v1`）
4. 同一页 **API Key 管理 → 创建 API Key**（只显示一次，立刻存进 `.env`）

> **注意**：华为云控制台改版较频繁，"领取额度"的入口位置可能变动。
> 找不到时优先看**控制台首页（总览）**的提示卡片，或用**顶部全局搜索框**直接搜 `MaaS`。
> **别把 GLM 系列当免费模型**——GLM 在华为云是按 token 计费的，没有免费额度。

### 3. 还没拿到 Key？先用「模拟模式」把链路跑通

`.env` 里有一行 `MAAS_MODE`，三种取值：

| 取值 | 行为 |
|---|---|
| `auto`（默认） | 配了 Key 就调真实模型；**没配则自动用内置模拟诊断** |
| `on` | 强制模拟，不发任何网络请求（断网 / 录屏演示用） |
| `off` | 强制真实模型，没配好直接报错（**正式提交前锁成这个**） |

模拟模式**不是编数据**——它读取真实巡检报告的问题清单，按类别（SSL / 性能 / 失效链接 / SEO / 无障碍…）
给出对应的根因判断和可执行处置建议，输出的 JSON 结构与真实模型完全一致，前端无需区别对待。
页面上会显示醒目的 **「AI：模拟模式」** 徽标，诊断结果里也会带一条显式声明，不会和真实结论混淆。

**这意味着：Key 还没到手时，你也可以先把整条链路开发和演示完，拿到 Key 后只要改 `.env` 就直接切换。**

### 4. 自检连通性

```bash
python scripts/smoke_maas.py
```

模拟模式下会直接告知"无需 Key，可继续"；真实模式下看到模型回话就说明配好了。

### 5. 启动

```bash
uvicorn app.main:app --reload
```

- 控制台：<http://127.0.0.1:8000/>
- 接口文档：<http://127.0.0.1:8000/docs>

加一个站点（比如你学校官网），点「巡检」，再点「AI 诊断」看效果。

## 常见问题

**MaaS 调不通？** 依次检查：区域是不是「西南-贵阳一」、有没有在控制台领取额度并开通预置服务、
模型 ID 是否与控制台「调用说明」完全一致、API 地址是否已删掉 `/chat/completions` 后缀。

**诊断结果是模拟的？** 看控制台顶部的 AI 徽标：显示「模拟模式」说明 `MAAS_MODE=auto` 且还没配 Key，
或 `MAAS_MODE=on`。配好 Key 并把 `MAAS_MODE` 设为 `off` 即可强制走真实模型。
`GET /api/status` 会返回 `ai_mode` 和 `mock_active` 两个字段，可用来做自动化检查。

**巡检很慢？** 链接探测会逐条请求页面内链，且失败项要做二次复核，因此比单纯 HEAD 慢一些。调试时用 `?deep=false`，或在 `.env` 里调小
`MAX_LINKS_PER_PAGE`。

**`.env` 会不会被提交上去？** 不会，`.gitignore` 已排除。**但请务必不要手动删掉那条规则**——
API Key 泄露是安全事故。
